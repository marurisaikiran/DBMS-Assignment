Question 1 — University Course Registration

Original (Flawed)

erDiagram
    STUDENT {
        string StudentID PK
        string Name
        string Email
    }
    COURSE {
        string CourseID PK
        string Title
        int Credits
        string Semester
        int Year
    }
    INSTRUCTOR {
        string InstructorID PK
        string Name
        string Department
    }
    CLASSROOM {
        string RoomNo PK
        string Building
    }
    STUDENT }o--o{ COURSE : ENROLLS
    INSTRUCTOR }o--o{ COURSE : TEACHES
    COURSE }o--|| CLASSROOM : HELD_IN

Semester/Year live on Course; Instructor, Classroom and Student all attach directly to Course — no Section.

Corrected

erDiagram
    COURSE {
        string CourseID PK
        string Title
        int Credits
    }
    SECTION {
        string SectionID PK
        string Semester
        int Year
    }
    INSTRUCTOR {
        string InstructorID PK
        string Name
        string Department
    }
    STUDENT {
        string StudentID PK
        string Name
        string Email
    }
    CLASSROOM {
        string RoomNo PK
        string Building
    }
    COURSE ||--o{ SECTION : OFFERS
    INSTRUCTOR ||--o{ SECTION : TEACHES
    STUDENT }o--o{ SECTION : ENROLLS
    SECTION }o--|| CLASSROOM : HELD_IN

New Section entity carries Semester/Year; Teaches, Enrolls and Held_In all reattach to Section.

Consultation and Prescription entities added; Dosage moved off Medicine and onto Prescription; Takes removed (derived).

Question 3 — E-Commerce Order Fulfilment

Original (Flawed)

erDiagram
    CUSTOMER {
        string CustomerID PK
        string Name
        string ShippingAddress
    }
    ORDER {
        string OrderID PK
        date OrderDate
        date ShipmentDate
    }
    PRODUCT {
        string ProductID PK
        string Name
    }
    SHIPMENT {
        string ShipmentID PK
        string Carrier
    }
    WAREHOUSE {
        string WarehouseID PK
        string Location
    }
    CUSTOMER ||--o{ ORDER : PLACES
    ORDER }o--o{ PRODUCT : CONTAINS
    ORDER }o--o{ SHIPMENT : SHIPPED_BY
    SHIPMENT }o--|| WAREHOUSE : FROM

ShippingAddress fixed on Customer; ShipmentDate fixed on Order; Contains has no Quantity; Shipped_By is Order-level, not line-level.

Corrected

erDiagram
    CUSTOMER {
        string CustomerID PK
        string Name
    }
    ORDER {
        string OrderID PK
        date OrderDate
        string DeliveryAddress
    }
    ORDERLINE {
        string OrderLineID PK
        int Quantity
    }
    PRODUCT {
        string ProductID PK
        string Name
    }
    SHIPMENT {
        string ShipmentID PK
        string Carrier
        date DispatchDate
    }
    SHIPMENTLINE {
        int ShippedQuantity
    }
    WAREHOUSE {
        string WarehouseID PK
        string Location
    }
    CUSTOMER ||--o{ ORDER : PLACES
    ORDER ||--o{ ORDERLINE : CONTAINS
    ORDERLINE }o--|| PRODUCT : FOR
    ORDERLINE ||--o{ SHIPMENTLINE : FULFILLED_BY
    SHIPMENT ||--o{ SHIPMENTLINE : INCLUDES
    SHIPMENTLINE }o--|| WAREHOUSE : SHIPPED_FROM

Address moved to Order; OrderLine carries Quantity; ShipmentLine ties a line to a shipment and warehouse for split/partial fulfilment.

Question 4 — Project Staffing and Roles

Original (Flawed)

erDiagram
    EMPLOYEE {
        string EmpID PK
        string Name
        string Role
    }
    PROJECT {
        string ProjectID PK
        string Title
        int HoursWorked
    }
    DEPARTMENT {
        string DeptID PK
        string Name
    }
    EMPLOYEE }o--o{ PROJECT : WORKS_ON
    EMPLOYEE }o--|| DEPARTMENT : BELONGS_TO
    EMPLOYEE }o--o{ PROJECT : MANAGED_BY

Role fixed on Employee; HoursWorked fixed on Project; Works_On/Managed_By are plain relationships with no time period.

Corrected

erDiagram
    EMPLOYEE {
        string EmpID PK
        string Name
    }
    PROJECT {
        string ProjectID PK
        string Title
    }
    ASSIGNMENT {
        string AssignmentID PK
        string Role
        date StartDate
        date EndDate
        int HoursWorked
    }
    MANAGER_HISTORY {
        string RecordID PK
        date StartDate
        date EndDate
    }
    EMPLOYEE ||--o{ ASSIGNMENT : WORKS_ON
    PROJECT ||--o{ ASSIGNMENT : STAFFED_BY
    EMPLOYEE ||--o{ MANAGER_HISTORY : MANAGES
    PROJECT ||--o{ MANAGER_HISTORY : MANAGED_BY

Role and HoursWorked move into Assignment; ManagerHistory retains every manager's tenure for audit. (Department/Belongs_To unchanged, omitted here.)

Question 5 — Airline Booking and Seat Assignment

Original (Flawed)

erDiagram
    PASSENGER {
        string PassengerID PK
        string Name
    }
    FLIGHT {
        string FlightNo PK
        date Date
        time DepartureTime
    }
    AIRCRAFT {
        string AircraftID PK
        string Model
    }
    AIRPORT {
        string AirportCode PK
        string City
    }
    SEATED_ON {
        string SeatNo
    }
    PASSENGER }o--o{ FLIGHT : BOOKS
    FLIGHT }o--|| AIRCRAFT : USES
    PASSENGER ||--o{ SEATED_ON : ""
    FLIGHT ||--o{ SEATED_ON : ""
    AIRCRAFT ||--o{ SEATED_ON : ""
    FLIGHT }o--|| AIRPORT : ORIGIN
    FLIGHT }o--|| AIRPORT : DESTINATION

Flight conflates flight-number and dated occurrence; Books has no PNR; Seated_On is ternary (Passenger-Flight-Aircraft), no segment anchor.

Corrected

erDiagram
    FLIGHT_NUMBER {
        string FlightNo PK
        time DepartureTime
    }
    FLIGHT_OCCURRENCE {
        string OccurrenceID PK
        date FlightDate
    }
    AIRCRAFT {
        string AircraftID PK
        string Model
    }
    PASSENGER {
        string PassengerID PK
        string Name
    }
    PNR {
        string PNRCode PK
    }
    PASSENGER_SEGMENT {
        string SeatNo
    }
    AIRPORT {
        string AirportCode PK
        string City
    }
    FLIGHT_NUMBER ||--o{ FLIGHT_OCCURRENCE : OPERATES_AS
    FLIGHT_OCCURRENCE }o--|| AIRCRAFT : USES
    FLIGHT_NUMBER }o--|| AIRPORT : ORIGIN
    FLIGHT_NUMBER }o--|| AIRPORT : DESTINATION
    PNR }o--o{ PASSENGER : INCLUDES
    PNR ||--o{ PASSENGER_SEGMENT : GENERATES
    PASSENGER ||--o{ PASSENGER_SEGMENT : ASSIGNED
    FLIGHT_OCCURRENCE ||--o{ PASSENGER_SEGMENT : COVERS

Flight split into FlightNumber/FlightOccurrence; PNR groups passengers+segments; PassengerSegment replaces the ternary, giving seat-per-segment.
